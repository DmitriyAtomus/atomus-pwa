# «Что закупить» — выпуск v2.46.286, 05.11.2026

Рабочий экран реализован поверх существующей модели закупок и подключён к новым API бэкенда `my-bot`. Первоначальный интерактивный макет `supply-shopping-20261105.html` сохранён как материал обсуждения; он по-прежнему работает только на демонстрационных данных в памяти браузера.

## Итоговое поведение

- Договор / «Куда» → изделие / группа → позиции. Реальное изделие берётся из расчёта производственной потребности (`plan_models`). Электрика текущего договора имеет источник «ЩУ - 005.004». Группу можно переименовать или назначить вручную.
- Выбор одной строки, всей группы или нескольких строк. Поставщик, группа и две даты назначаются массово. Количества остаются индивидуальными: выбор 10 строк не заменяет количества деталей на 10.
- «Изготовят к» и «Придёт к нам» редактируются независимо, с сохранением прежних значений, автора и времени в истории. Для заказа дата поступления — существующее `expected_date`, готовность — новое `ready_date`.
- «Подготовить заказ» создаёт только черновики выбранных потребностей. Поставщики, назначения, группы и сроки разделяются. Сохраняются количества, группа и сроки. Отправка поставщику выполняется отдельно в существующей карточке ORD.
- Переименование позиций и «Куда» меняет подписи рабочего списка. «Убрать из списка» скрывает строку или назначение с восстановлением через «Убранное». Заказ, оплата и складские движения сохраняются.
- Поставщик закупки хранится отдельно от глобального поставщика номенклатуры. Поставщик оформленного заказа остаётся связанным со счётом. Для таких заказов доступно существующее изменение «Куда».
- Если один компонент нужен нескольким договорам, общая потребность показана один раз в «Общих потребностях». Автоматического дублирования количества по договорам нет.
- Старый вид доступен. Правило семи дней в «Ждём поставку» сохранено.

## Сохранение и конфликты

API `/api/supply/board`, `/history`, `/change`, `/drafts`. Запись требует существующего права управления снабжением. Скрытия, подписи, группы, поставщик и сроки хранятся на сервере; запись пакета атомарная. Проверяются ревизии, состояние источника и количество при создании черновиков. Идемпотентный идентификатор запроса предотвращает повторный заказ. Новая потребность с другим составом договоров/изделий получает новый ключ и не наследует скрытие старой.

Если обязательные данные не загрузились, массовые изменения блокируются с кнопкой повторной загрузки. Смена фильтров и поиск снимают выделение.
