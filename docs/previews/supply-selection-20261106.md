# Закупки: массовый поставщик и покрытая потребность

Кандидат выпуска v2.46.287, 06.11.2026. В рабочую CRM не опубликован.

## Поведение

- «Поставщик выбранным» находится рядом с «Выбрать все» в группе. Без выделения можно назначить поставщика всей группе.
- Нажатие «Выбрать» в выделенной строке назначает поставщика всем выбранным потребностям. Окно явно показывает число строк. Невыделенная строка изменяется отдельно; количества сохраняются.
- В каждом договоре отдельно показаны «Нужно заказать» и «Заказы и счета». Счёт, сумма, статус и раскрываемый состав находятся в строке своего заказа.
- Для старых заказов без складского мостика backend распознаёт полное покрытие потребности при точном названии товара, совместимой единице, единственном договоре и единственной строке подходящего заказа.
- Совпадение не меняет склад, оплату, документы или справочники. Другие мощности, разные договоры, дубли номенклатуры, несколько заказов и неполное покрытие автоматически не объединяются.

## Проверенный случай

Дмитрий подтвердил: нужно докупить 14 ТЭНов, заказано 30. Проверка текущей базы только для чтения и отдельной копии подтвердила:

- НВП-15-380-AISI: 2 изделия × 11 ТЭНов = 22.
- На складе 8; потребность к закупке 14.
- ORD-464, счёт №3384: 30 ТЭНов, этап «На оплату».
- У компонента 507 отсутствует `supply_item_id`, хотя название и единица однозначно совпадают с позицией заказа того же договора.
- После исправления: одна строка ORD-464, «нужно 14 / в заказе осталось 30 / докупить 0 / сверх потребности 16». Эти 16 не объявляются поступившими на склад.
- Показанные на исходной фотографии 24 не соответствуют текущему расчёту; историческая причина этого значения по фотографии не установлена.
